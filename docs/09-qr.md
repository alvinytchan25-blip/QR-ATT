# Phase 8 — QR Generation (v:1, Cloud-Backed)

## Goal

Keep the QR format in one module so generation and validation cannot drift, and
only show a QR after its event has actually been saved to Supabase.

## The contract

The QR text is JSON:

```json
{
  "v": 1,
  "event": "EVT-2026-0002",
  "title": "Founders Day Assembly",
  "start": "2026-09-03T09:00:00Z",
  "end": "2026-09-03T11:00:00Z"
}
```

`v` is the format version, `event` is the public event code, and `title`,
`start`, and `end` are optional.

## `lib/qr.ts`

| Export | Purpose |
|---|---|
| `QRPayload` | `{ v: 1; event: string; title?; start?; end? }` |
| `buildQRPayload(event)` | Maps `eventId → event` and returns the JSON string |
| `ParseQRResult` | `{ ok: true, payload } \| { ok: false, message }` |
| `parseQRPayload(raw)` | Parses and validates the scanned text |

`buildQRPayload` only adds optional fields when they are present, keeping the
QR small.

## Wiring

- `app/(tabs)/teacher.tsx` imports `buildQRPayload`. `handleCreateEvent` awaits
  `createEvent(event)`, returns early on `{ error }`, and only then calls
  `setPayload(buildQRPayload(event))`, so the QR is cloud-backed.
- `lib/attendance.ts` imports `parseQRPayload`. `registerAttendance` handles
  `{ ok: false }` before reading `payload`, then continues with the time-window,
  event lookup, and attendance insert.

The lab references `lib/database.ts`; this repo uses the Phase 9 split, so the
scanner side lives in `lib/attendance.ts`.

## Hardened validation

The lab's parser checks `parsed.v` directly. Because `JSON.parse('null')`
succeeds and returns `null`, reading `parsed.v` would throw. The repo adds:

```ts
if (!parsed || typeof parsed !== 'object' || parsed.v !== 1 || ...)
```

so valid-but-wrong JSON (`null`, numbers, strings) is rejected with
“Not an attendance QR code.” instead of crashing.

## Negative tests

| QR text | Result |
|---|---|
| `not json` | “Invalid QR code.” |
| `null` | “Not an attendance QR code.” |
| `{"event":"X"}` | “Not an attendance QR code.” (no `v:1`) |
| `{"v":2,"event":"X"}` | “Not an attendance QR code.” |
| `{"v":1,"event":""}` | “Not an attendance QR code.” |

## Verification

1. `npm run typecheck` — no errors.
2. Teacher creates an event; the QR appears only after the row is in `events`.
3. The payload text shows `v:1`.
4. Student scans it → “Attendance recorded!”
5. Invalid/wrong-version QRs show the messages above.
